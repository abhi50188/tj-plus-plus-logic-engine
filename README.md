# TJ++ Logic Engine: Cognitive Auditing for Natural Language

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.22057917.svg)](https://doi.org/10.5281/zenodo.22057917)

The TJ++ Logic Engine is a deterministic, content-opaque framework that models natural language texts as directed dependency graphs to mathematically audit structural soundness, enforce cognitive coherence, and mitigate AI hallucinations. 

Because the engine is completely content-opaque—treating concepts and dependencies as abstract mathematical structures—the raw PDF whitepaper functions directly as the source code, while any sufficiently advanced Large Language Model (LLM) acts as the compiler and runtime environment.

---

## 🚀 How to Run the TJ++ Engine on Your Text

You do not need to write any custom code or maintain a software pipeline to use this framework. To execute a structural audit, simply follow these steps:

1. **Prime the LLM**: Upload the `tj_plus_plus_whitepaper_v45.pdf` or paste the contents of the `TJ++_Revised.md` specification file into your LLM's active prompt window.
2. **Confirm Compilation**: Wait for the LLM to acknowledge the paper's mathematical definitions and logic layers.
3. **Execute the Audit**: Paste your text and run the following command:
   > *"Let's TJ++ the following draft paragraph."*

## 🛠️ The Pipeline Layers Inside the Engine

When you run the engine, the LLM compiler processes your prose through six distinct mathematical layers:

* **Layer 0: Node-Sourcing** – Walks the external rubric or requirements document, using a binary Completeness Test to establish the objective Basis Vector ($B_0$).
* **Layer 1: Non-Crossing Combinatorics** – Runs a linear-time stack-based walk over reading sequences to ensure nested logical threads nest cleanly and do not cross.
* **Layer 2: Jacobian Loop Check** – Traverses dependency equations and calculates eigenvalues. Any non-zero eigenvalue mathematically exposes an ungrounded circular deadlock loop.
* **Layer 3: Spectral Laplacian Check** – Symmetrizes dependencies into an undirected Graph Laplacian matrix ($L = D - A$) to isolate disconnected "floating islands" of AI-generated filler.
* **Layer 4: Basis-Shift Circuit Check** – Compares actual text against the expected Basis Vector ($S = B_0 - R$) to instantly flag and shear thematic drift.
* **Layer 4.5: Minimal-Basis Pruning** – Recursively proposes node cuts, running Laplacian and Requirement-Response checks to trim redundant clutter until a stable mathematical fixed point is reached.
* **Layer 5: Oracle-Splay Attention Mapping** – Simulates reading access operations on a binary search tree to ensure the structural shape of your text matches an idealized reading path.
